# Клиент UpdateHub

Обновляет одну папку на машине под Ubuntu или Astra Linux по данным сервера.

Ничего, кроме `bash`, `curl` и `coreutils`, не требуется. `jq` не нужен:
сервер отвечает клиентской части текстом в формате `md5sum` и строками
`ключ=значение` именно ради этого.

## Установка

Каталог переносится на машину любым способом — тем же носителем, которым
приносят файлы для первой заливки.

```
sudo ./install.sh
sudo nano /etc/updatehub/updatehub.conf   # заполнить SERVER_URL
updatehub selftest
```

`install.sh` кладёт программу в `/opt/updatehub`, ссылку в `/usr/local/bin`,
настройки в `/etc/updatehub` и модули systemd. Существующий файл настроек
не перезаписывается: при обновлении клиента заново вводить адрес и пароль
незачем.

## Ввод машины в работу

```
updatehub enroll                        # заявка на регистрацию
                                        # администратор одобряет её и выдаёт права
updatehub seed /media/usb/updatehub     # первая заливка с носителя, если он есть
updatehub sync                          # обновление
```

Первая заливка с носителя нужна не всегда, но обычно нужна: образ размером
около шести гигабайт по каналу 2 Мбит/с идёт примерно семь часов. С флешки
это минуты, а сервер потом досылает только разницу.

Ежедневное обновление включается модулем systemd:

```
sudo systemctl enable --now updatehub.timer
```

Таймер разбрасывает запуски случайной задержкой до часа. Без неё все машины
пошли бы за обновлениями одновременно и разделили между собой узкий канал.

## Команды

| Команда | Что делает |
| --- | --- |
| `enroll [примечание]` | подаёт заявку на регистрацию компьютера |
| `sync` | обновляет рабочую папку |
| `check` | показывает разницу, ничего не меняя |
| `status` | показывает состояние машины, не обращаясь к серверу |
| `seed <каталог>` | начальная заливка со съёмного носителя |
| `logout` | отзывает сохранённые токены |
| `selftest` | проверяет окружение, настройки и связь |

## Как устроено обновление

1. Программа строит манифест рабочей папки командой `md5sum` и отправляет
   его серверу как есть.
2. Сервер отвечает планом: что скачать, что на машине лишнее, сколько это
   весит.
3. Проверяется свободное место: файлы сначала складываются во временный
   каталог целиком.
4. Файлы скачиваются с докачкой. Обрыв на семичасовой передаче — обычное
   дело, поэтому загрузка продолжается с прерванного места, а не начинается
   заново.
5. Скачанное проверяется командой `md5sum -c` по тому же списку, который
   прислал сервер.
6. Только после успешной проверки файлы переносятся в рабочую папку.
   Не прошло проверку — рабочая папка остаётся нетронутой.
7. Временный каталог очищается полностью.

**Лишние файлы не удаляются.** Файлы, которых нет на сервере, программа
только перечисляет: решение об их судьбе принимает человек.

## Коды завершения

Их читает systemd и человек в журнале.

| Код | Значение |
| --- | --- |
| 0 | успех |
| 1 | ошибка использования или неизвестная неполадка |
| 75 | временная неполадка: нет связи, мало места, обрыв загрузки |
| 77 | отказано в доступе: неверный пароль или нет прав на компьютер |
| 78 | ошибка настройки: компьютер не заведён, не заполнен файл настроек |

Разделение не формальное: код 75 означает «повторить позже», а 77 и 78 —
«само не исправится, нужен человек».

## Учётные данные

Пользователь обязан авторизоваться — сервер не отдаёт файлы анонимно.
Возможны два способа:

- **Оставить `USERNAME` и `PASSWORD` пустыми.** Программа спросит их при
  запуске. Для обновления по расписанию не подходит: спрашивать некого,
  и запуск завершится кодом 78.
- **Заполнить их в файле настроек.** Файл при этом обязан иметь права 600 —
  `install.sh` их и ставит.

После первого входа программа хранит refresh-токен в `/var/lib/updatehub`
с правами 600 и обновляет по нему access-токен. Пароль при этом больше
не передаётся.

## Тесты

```
./tests/run-tests.sh
```

Сторонних средств не требуется: на машине в закрытом контуре их взять
неоткуда. Проверки двух видов — подпрограммы по отдельности и весь ход
обновления против подставного сервера на Python: вход, сравнение манифестов,
обрыв связи с докачкой, протухший токен, испорченная передача, нехватка
места, неверный пароль.

Подставной сервер проверяет именно клиент. Соответствие самого протокола
проверяют тесты сервера на C#, где поднимается настоящее приложение.

## Идентификатор компьютера

Создаётся при первом запуске в `/etc/updatehub/client-id` и не меняется:
по нему привязаны выданные права и вся история обращений. **Удалять его
нельзя** — машина превратится в неизвестную, и заявку придётся подавать
заново.

Отдельно передаётся отпечаток железа: он собирается из серийных номеров
материнской платы и корпуса и переживает переустановку системы. По нему
администратор узнаёт ту же машину с новым идентификатором.
